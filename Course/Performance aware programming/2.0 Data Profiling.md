
This part was about profiling the programs and understanding how the the CPU ticks and the OS ticks differ

Internally both of them depend on the RDTSC (read time stamp counter). Which is a simple ASM instruction at its core, which send the tick value back from when the CPU was started. Before the multi core CPU's this was based on the exact frequency of the CPU, but with multi core and each core operating on different frequencies based on the usage, this represents a averaged out value for any for the core i.e 1 value for every core whether or not its operating at the same frequency.

Looked at various method of profiling with the instrumentation based profiling for the nested and the recursive blocks.

Also looked at the profilin overhead with the implementation which increased when the call to same anchors crossed over 10millions.
